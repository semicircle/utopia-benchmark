Utopia

Can your AI code in a language that didn't exist this morning?

Every run of Utopia generates a brand-new programming language from a seed: fresh keywords, its own syntax, and false friends — semantics that look familiar but behave differently (indices from 1, right-to-left operator grouping, switch fallthrough…). The model gets the manual and must write working programs. Nothing it memorized applies.

Why

Today's coding benchmarks mostly measure recall. Models have seen millions of Python and JavaScript programs, so "write a todo app" often means remembering one rather than engineering one. Prior work backs this up: frontier models that score ~100% on problems in Python drop to 0–11% on the same problems in esoteric languages (EsoLang-Bench).

Utopia measures what is left when recall is taken away:

  • In-context learning: learning a whole language and platform from its docs.
  • Following the spec over habit: semantics that look familiar but behave differently ("false friends").
  • Engineering: building working, multi-part apps, not toy algorithms.
  • Debugging the platform itself: finding and working around seeded VM bugs and docs that are wrong.

The results on this page cover the first two. Multi-part apps and seeded platform bugs are on the roadmap.

Method

  
    
    
  1. Generate. A seed produces a whole language: a conlang lexicon, independent
      syntax styles for functions, conditionals, switches and loops (C-like, Pascal-like, BASIC-like or
      assembly-like), operator spellings, and ten semantic knobs. A reference manual is generated from a
      fixed template, and every example in it is executed to produce the output shown.
    2. 
    
  2. One-shot mode. The model receives the manual and all tasks in one prompt, with no
      tools, and must write every solution without running anything. It is cheap and measures pure
      in-context learning.
    3. 
    
  3. Agent mode. The model works as a coding agent in a fresh workspace with the
      manual, the tasks and the language's toolchain, using three tools (run a shell command, read a
      file, write a file), the same for every provider. The workspace sits outside the benchmark's
      source tree, and every shell command is audited for attempts to look elsewhere. Grading rebuilds
      the toolchain, so nothing the agent touched is trusted.
    4. 
    
  4. Grade. Solutions run against hidden tests; a task passes only if every test's
      output matches exactly.
    5. 
  

  
Caveats: 17 tasks in three tiers, few runs per arm, so differences of a task or two
    are noise. Any Anthropic or OpenAI-compatible endpoint can be run with an API key and a model name.
